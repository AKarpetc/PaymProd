## Общее описание приложения `PaymProdNet9`

### Назначение

`PaymProdNet9` — это настольное WPF‑приложение для:

- планирования банкетов и ведения текущего меню;
- ведения справочников блюд и продуктов;
- расчета потребности в продуктах и себестоимости;
- формирования отчетов по меню и по товарам (Word / Excel / печать);
- управления базой данных (резервные копии, восстановление, загрузка стартовой БД).

База данных — SQLite, один файл `MenuCalc.db` в каталоге:

- `%LOCALAPPDATA%\PaymProdNet9\MenuCalc.db`

Приложение всегда работает именно с этой копией, независимо от каталога установки.

### Основные разделы интерфейса

#### Главное окно навигации `MainNavigationWindow`

- **Левая панель** — кнопки навигации:
  - `Текущее меню` → страница `CurrentMenuPage`
  - `Сохраненные меню` → `SavedMenusPage`
  - `Справочник блюд` → `DelicatesPage`
  - `Справочник продуктов` → `ProductsPage`
  - `Общая цена продуктов` → `ProductPricesPage`
  - `Единицы измерения` → `MeasuresPage`
  - `Типы продуктов` → `ProductTypesPage`
  - `Типы блюд` → `DelicateTypesPage`
  - `Управление базой данных` → `DatabaseManagerPage`
  - `Отчет по товарам` → `ProductsReportPage`
  - `Сводная таблица` → `SummaryTablePage` (через данные текущего меню)
  - `Отчет по меню` → `PrintMenuPage`

- **Центральная область** — `Frame`, в который подгружается выбранная страница.
- **Верхняя панель**:
  - заголовок текущей страницы (`PageTitle`);
  - кнопка «Назад» (работает как стек навигации);
  - кнопка выхода из приложения.

При любой навигации отображается затемняющий overlay с индикатором загрузки.  
Навигация выполняется через сервис `NavigationService.Instance`, который хранит стек страниц.

### Основной рабочий процесс

1. **Создание или открытие меню**:
   - через `Текущее меню` (`CurrentMenuPage`) или старую страницу `MenuPage` (для совместимости);
   - вводятся: название банкета, количество гостей, дата/время начала, описание;
   - после подтверждения создается запись в таблице `Menus` (через `MenuRepository.CreateMenu`), предыдущее открытое меню автоматически закрывается.

2. **Подбор блюд в меню**:
   - выбор доступных блюд из справочника (`Delicates`);
   - добавление/удаление блюд в меню (`Menu_Delicates`);
   - настройка количества порций и состава конкретного блюда в меню (редактирование компонентов в `Components1`).

3. **Расчет продуктов**:
   - при сохранении и при формировании отчетов происходит перерасчет количества товаров:
     - вес/количество компонентов блюда умножается на число порций;
     - выполняется перерасчет в фасовку и округление по правилам из таблицы `Mera`
       (поля `RoundingPrecision`, `MenuRoundingPrecision`, `Fass`, `Fass_Izmer`).

4. **Работа со справочниками**:
   - продукты (`Producrs`), типы продуктов (`Produkt_Type`), единицы измерения (`Mera`),
     блюда (`Delicates`), типы блюд (`Type_Del`);
   - все формы следуют одному паттерну: список + отдельная панель редактирования/создания.

5. **Отчеты**:
   - **Отчет по меню** (`PrintMenuPage` / `MenuPrinter.PrintMenu`) — печатная форма меню с составом блюд и (опционально) ценой;
   - **Отчет по товарам** (`ProductsReportPage` / `MenuPrinter.PrintReport`) — агрегированный список продуктов с итоговым количеством и ценой;
   - **Сводная таблица** (`SummaryTablePage`) — детальный список компонент по блюдам с итоговыми значениями (основа для Excel‑экспорта);
   - **Старый отчет** (`ReportPage` / `ReportWindow`) — упрощенный вариант отчета по товарам (оставлен для совместимости).

### Важные скрытые/неочевидные правила

#### Округление количеств

- Округление количеств в отчетах и меню выполняется **вверх** (через `Math.Ceiling`) по точности из `Mera.MenuRoundingPrecision`:
  - `0` — округление до целых (например, упаковки);
  - `1`, `2` и т.п. — до десятых/сотых и т.д.
- При наличии фасовки (`Fass`, `FassIz`):
  - если `Itog` (натуральное количество) ≥ `Fass`, то количество пересчитывается в фасовку,
    и единица измерения меняется на `FassIz`;
  - если `FassIz` совпадает с базовой мерой (`Mera`), то пересчета в фасовку **не происходит**,
    даже если `Fass > 0` (логика как в отчете по товарам).

Пример фрагмента кода (упрощенный) для перерасчета в фасовку:

```csharp
if (component.Fass > 0 &&
    !string.IsNullOrWhiteSpace(component.FassIz) &&
    NormalizeUnit(component.FassIz) != NormalizeUnit(baseUnit) &&
    totalWeight >= component.Fass)
{
    var packageCount = totalWeight / component.Fass;
    displayValue = Math.Ceiling(packageCount * 100) / 100; // округление вверх
    displayUnit = component.FassIz;
}
else
{
    displayValue = Math.Ceiling(totalWeight * 100) / 100;
    displayUnit = baseUnit;
}
```

#### Расчет цен по **округленному** количеству

- В отчете по товарам `ProductsReportPage`:
  - изначально в `GroupedProduct.TotalPrice` хранится стоимость по «сырым» итогам (`Itog`, `ItogFass`);
  - после форматирования количества через `FormatAmountWithRoundedValue` вызывается `RecalculatePrice`, которая:
    - вычисляет **цену за единицу** как `TotalPrice / исходноеКоличество`;
    - умножает ее на **округленное количество**, чтобы цена соответствовала тому, что видит пользователь.

Условно:

```csharp
var unitPrice = product.TotalPrice / (decimal)originalAmount;
var finalPrice = decimal.Round(unitPrice * (decimal)roundedAmount, 2);
```

#### Авто‑добавление хозтоваров в меню

- В `ProductsPage` у продукта есть флаг `AutoAdd` (в базе — поле `Avtomat` / логика в `MenuRepository.AddAutoProductToMenu`):
  - при сохранении такого продукта метод `AddAutoProductToOpenMenu` пытается найти **текущее открытое меню**;
  - если открытое меню есть, продукт автоматически добавляется в него как «хозтовар» с учетом количества гостей;
  - если открытого меню нет — продукт просто сохраняется, в лог пишется диагностическое сообщение.

Это скрытое поведение: пользователь может не ожидать, что изменение справочника продуктов сразу меняет текущее меню.

#### Фильтрация и скрытие позиций

- На странице `CurrentMenuPage` есть переключатель «Показать товары» / «Скрыть товары»:
  - внутренний флаг `_showHiddenItems` управляет тем, показываются ли служебные/авто‑добавленные позиции;
  - метод `UpdateMenuFilter` фильтрует `MenuDel_act` по этому флагу, не затрагивая данные в базе.

#### Работа с базой данных только через AppData

- В `App.xaml.cs` и `DatabaseHelper` база всегда ищется и создается только в:

```csharp
var appDataDir = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "PaymProdNet9");
var dbPath = Path.Combine(appDataDir, "MenuCalc.db");
```

- Путь `Program Files\PaymProdNet9\MenuCalc.db` **никогда** не используется для записи, чтобы избежать ошибок доступа.
