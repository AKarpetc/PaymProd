## Справочники продуктов, блюд, типов и мер

В этом документе описаны страницы:

- `ProductsPage` — справочник продуктов.
- `ProductPricesPage` — редактирование цен продуктов (общих и для конкретного меню).
- `ProductTypesPage` — типы продуктов.
- `MeasuresPage` — единицы измерения.
- `DelicatesPage` — справочник блюд.
- `DelicateTypesPage` — типы блюд.
- `DictionariesPage` — «комбинированный» режим редактирования (старый интерфейс).

---

### `ProductsPage` — справочник продуктов

Основной экран работы со справочником `Producrs`.

#### Режимы работы

- `ProductsListView` — список всех продуктов.
- `ProductEditView` — режим создания/редактирования одного продукта.
- Переключение между режимами:
  - `ShowListView()` — показать список;
  - `ShowEditView(bool isEdit)` — открыть форму редактирования.
- При попытке навигации «Назад» во время редактирования переход отменяется, и вместо этого вызывается `ShowListView()` — это скрытое поведение, чтобы пользователь не потерял несохраненные изменения.

#### Список продуктов

- Загружается из `ProductRepository.GetAllProducts()` в кэш `_productsCache`.
- Поиск (`ProductSearchBox`):
  - фильтрует по полям `Name`, `Type`, `IzName` (единица измерения фасовки);
  - поиск выполняется целиком по кэшу без повторных обращений к базе.

#### Поля продукта

Основные свойства, которые редактируются в форме:

- `Name` — название.
- `Type` — тип продукта (`Produkt_Type`).
- `Mera` (`Ves` в `ProductView`) — базовая единица измерения (г, кг, шт и т.п.).
- `Fass` — размер фасовки (например, 450 г в пачке).
- `FassIz` (`IzName`) — единица фасовки (пач, бут, рулон и т.п.).
- `Count` — базовое количество для расчета (например, на одного человека).
- `CountPeople` — «на сколько людей» рассчитан `Count`.
- `Price` — базовая цена продукта (общая, не привязанная к конкретному меню).
- `AutoAdd` / `Avtomat` — флаг «автоматически добавлять в отчет по товарам/меню как хозтовар».

#### Скрытая логика: авто‑добавление хозтоваров

При сохранении продукта с флагом `AutoAdd` код вызывает:

```csharp
AddAutoProductToOpenMenu(productId, baseCount, countPeople, mainCount: true);
```

Метод:

```csharp
private void AddAutoProductToOpenMenu(int productId, decimal baseCount, int countPeople, bool mainCount)
{
    var menuRepository = new MenuRepository();
    var openMenu = menuRepository.GetOpenMenu();
    if (openMenu == null) return; // если меню не открыто — просто выходим

    menuRepository.AddAutoProductToMenu(openMenu.Id, productId, baseCount, openMenu.CountP);
}
```

То есть при изменении/создании продукта с `AutoAdd` он **сразу** добавляется в текущее открытое меню (если оно есть).  
Это важно учитывать операторам — изменение справочника может изменить существующее меню.

### `ProductPricesPage` — цены продуктов

Страница для редактирования цен:

- **общих цен** (справочник `Producrs.Price`), если `menuId == null`;
- **цен конкретного меню** (`Menu_Product_Prices`), если `menuId` передан в конструктор.

#### Режимы отображения

- Если `_menuId == null`:
  - скрываются колонки `BasePriceColumn` и `SaveToBasePriceColumn`;
  - редактируется только базовая цена продукта.
- Если `_menuId.HasValue`:
  - показываются колонки:
    - «Старая цена» (базовая цена из справочника);
    - флаг «Сохранить в цену» — если включен, новая цена из меню может быть записана обратно в справочник при сохранении.

#### Загрузка данных

1. `LoadProducts()`:
   - если это меню (`_menuId.HasValue`) — берет только продукты, реально используемые в меню: `GetMenuProducts(menuId)`;
   - иначе — все продукты: `GetAllProducts()`;
   - для каждого продукта:
     - `BasePrice = Price` (цена из справочника);
     - `OriginalPrice = Price`;
     - `SaveToBasePrice = true` (по умолчанию все изменения можно сохранить в справочник).
2. `LoadMenuPrices()` (только для меню):
   - подгружает цены из таблицы `Menu_Product_Prices`;
   - если цена найдена — отображается цена из меню, иначе — базовая.

#### Фильтрация по типу продуктов

- Кнопки типов формируются из `ProductRepository.GetProductTypes()`:
  - при режиме меню показываются только те типы, которые реально присутствуют среди загруженных продуктов;
  - при режиме общих цен — все типы.
- Нажатие на кнопку меняет `_currentTypeFilter` и перезагружает список продуктов.

#### Сохранение изменений (основные правила)

- При изменении цены в гриде:
  - устанавливается флаг `IsModified` у соответствующего `ProductView`;
  - далее при нажатии «Сохранить»:
    - для общих цен — обновляется `Producrs.Price`;
    - для меню:
      - создается/обновляется запись в `Menu_Product_Prices`;
      - если `SaveToBasePrice == true`, базовая цена в справочнике также обновляется.

Это позволяет настраивать временные цены в рамках конкретного меню без обязательной смены базовых цен.

### `ProductTypesPage` — типы продуктов

Работает со справочником `Produkt_Type`.

- Виды **типов продуктов** (овощи, мясо, рыба и т.п.).
- Параметры:
  - `Name` — название типа.
  - `SortOrder` — порядок сортировки.
  - `HideInMenu` — флаг «скрывать в меню» (используется при формировании меню и отчетов).

Особенности:

- Страница имеет два вида:
  - список типов;
  - панель редактирования.
- Навигация назад из режима редактирования перехватывается, чтобы не потерять данные.
- При удалении типа выполняется прямой вызов `_productRepository.DeleteProductType(id)` — следует быть осторожным, если к типу привязаны продукты.

### `MeasuresPage` — единицы измерения

Работает со справочником `Mera` и критически важна для всех расчетов.

Поля меры:

- `Name` — название (г, кг, л, шт, порция и т.п.).
- `Fass` — размер фасовки при переходе «вверх» (например, 1000 г → 1 кг).
- `FassIzmer` — единица фасовки («кг» для граммов, «л» для миллилитров и т.п.).
- `RoundingPrecision` — точность округления в натуральных единицах.
- `MenuRoundingPrecision` — точность округления в отчетах по меню/товарам.

**Скрытая, но важная логика:**

- При форматировании количеств:
  - для натуральных единиц (`г`, `кг`, `л`, `мл` и т.п.) используется конвертация вверх/вниз по цепочке мер, основанная на `Fass`/`FassIzmer`;
  - при малых значениях (например, < 1 кг) код может автоматически «спуститься» до граммов, используя вспомогательный поиск дочерней меры.
- В форме редактирования по умолчанию выбирается округление до сотых (индекс `1` в ComboBox), но фактическая точность зависит от выбранных значений.

Пример влияния настроек:

- Если `Name = "кг"`, `Fass = 1000`, `FassIzmer = "г"`, `MenuRoundingPrecision = 2`,  
  то 1500 г могут быть показаны как `1.50 кг`.
- Если `MenuRoundingPrecision = 0`, то то же самое будет показано как `2 кг` (округление вверх).

### `DelicatesPage` — справочник блюд

Работает со справочником `Delicates` и их составом (`Components`).

#### Основные функции

- Список блюд с поиском по:
  - названию блюда (`Name`);
  - типу блюда (`Type`).
- Режимы:
  - просмотр списка (`ListViewPanel`);
  - создание/редактирование блюда (`EditViewPanel`).
- В составе блюда:
  - `DelicateComponentsGrid` показывает компоненты (`Components`);
  - `AvailableProductsList` — список продуктов, которые можно добавить.

#### Неочевидные моменты

- Список блюд **по умолчанию сортируется по убыванию Id** — новые блюда всегда сверху.
- При переключении в режим редактирования:
  - поле `_isEditMode` определяет, будет ли вызван `AddDelicate` или `UpdateDelicate` в репозитории;
  - если блюдо уже используется в меню, изменения состава могут изменить расчеты в отчетах (нет дополнительной проверки).

Поиск в справочнике блюд:

```csharp
var filtered = _delicatesCache.Where(d =>
    d.Name.ToLower().Contains(searchText) ||
    (d.Type != null && d.Type.ToLower().Contains(searchText))
).OrderByDescending(d => d.Id);
```

Это означает, что поиск не учитывает состав (компоненты); для поиска по ингредиентам нужно использовать отчеты.

### `DelicateTypesPage` — типы блюд

Аналогичен `ProductTypesPage`, но для таблицы `Type_Del`:

- `Name` — название типа блюда (салаты, горячие закуски, гарниры и т.д.).
- `SortOrder` — порядок отображения в справочниках и меню.

Используется при:

- фильтрации блюд по типам в `CurrentMenuPage` и `MenuPage`;
- группировке в `PrintMenuPage` и других отчетах по меню.

---

### `DictionariesPage` — комбинированный режим (старый интерфейс)

Окно «Правка справочников» в старом интерфейсе (`DictionariesWindow`) открывает страницу `DictionariesPage`.

Функции:

- в одной форме одновременно:
  - список блюд и их состав;
  - список продуктов;
  - выпадающие списки типов блюд, типов продуктов и единиц измерения.
- больше подходит для «массовых правок»:
  - можно быстро переключаться между блюдами и их составом;
  - изменять типы для блюд/продуктов.

Сейчас основной и более дружелюбный для пользователя вариант — отдельные страницы:

- `DelicatesPage`, `ProductsPage`, `ProductTypesPage`, `MeasuresPage`, `DelicateTypesPage`.
